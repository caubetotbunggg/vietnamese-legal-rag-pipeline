# Application branch integration

The original `main` branch contained the early legal document data pipeline. The complete RAG application was developed on other branches and is now integrated into `main` with a merge commit.

## Selected source

| Branch | Reviewed tip | Role |
| --- | --- | --- |
| `dev` | `6f30dfc` | Selected application source: deployment implementation plus later UI, prompt, and test updates |
| `dev-test-deploy` | `f7846b3` | Complete deployment application; an ancestor of `dev` |
| `dev-test-deploy-v2` | `07b69fb` | Earlier deployment/revert variant |
| `dev-tuan-10` | `933407a` | Earlier weekly integration variant |
| `high_precision_mode` | `9e4f170` | Separate experimental retrieval/reranking configuration |
| Weekly and backup branches | Various | Historical snapshots and alternatives |

`dev` is 12 commits ahead of `dev-test-deploy` and contains every commit from that branch. Branch selection used ancestry, source layout, API/service implementations, UI, configuration, and test changes. Experimental branch features were not combined indiscriminately with the newer application.

## Merge resolution

- Use the application layout from `dev`: `app/`, `scripts/`, `tests/`, monitoring, and deployment files.
- Replace the early data-only README with documentation for the complete RAG application.
- Follow `dev` in keeping `data/` and generated bytecode out of Git. The old corpus remains available at commit `3c04681`.
- Preserve checkout-independent paths and place runtime logs under the repository's `log/` directory.
- Repair module imports for `python -m scripts.run_crawl` and centralize assembly paths.
- Accept both existing title-string metadata and structured metadata in retrieval responses.
- Replace unsupported `DataType.JSON` with `DataType.TEXT` to match the title strings written by the indexing script.
- Run isolated tests in CI instead of relying on the deleted Conda environment file, a stale test path, or production smoke-test URLs.

## Validation scope

The Python 3.11 environment installed the declared application/development requirements. Twelve isolated service/API tests passed locally, covering retrieval results/errors, metadata compatibility, RAG response/validation, empty-choice retries, and mounting the UI/API documentation. The data modules were also exercised on a temporary fixture through crawl, fetch, parse, clean, chunk, assembly, and manifest generation with mocked HTTP.

Weaviate, Gemini/Elysia reasoning, hosted query embeddings, and Groq were not exercised against live credentials. These checks establish integration behavior, not legal answer accuracy or deployed service availability. Current limitations are listed in the root README.
